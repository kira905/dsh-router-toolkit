# 设计说明：为什么不做什么

成熟项目的 README 里，写「我们不做什么」往往比写「我们做什么」更能立住边界。
下面每条都不是欠账，是**边界**——做了就等于变成另一个东西。

| # | 永远不做 | 为什么 |
|---|---|---|
| 1 | **不做全权 shell** | 这个角色的价值就在"它没手"。给它全权 = 它必然长成第二个全能管家，与一条普通主线没有区别，只多一层转发。 |
| 2 | **不带任何入站通道**（IM / 群机器人 / 邮件） | 通道实现是部署事实（appId、openid、白名单、群策略），且每个平台的协议与合规面都不同。通道一旦进来，本仓就变成"某个版本的部署包"。 |
| 3 | **不带部署事实**（盘符、固定端口、目录名、工作区 uuid、回滚点路径） | 一行代码离开这台机器就报错的东西不是能力。默认值一律中性，覆盖一律走参数 / 环境变量。 |
| 4 | **不做自动清空上下文 / 自动 compact** | 自动清 = 可能把还没落档的结论一起丢掉。清空这一步永远留给人按。 |
| 5 | **不代人对真人说话** | 投话只投给"会话"（agent），不投微信 / 群 / 邮件。这在某些部署里是红线，在开源版里是设计。 |
| 6 | **不建卡、不验收卡、不改卡状态** | 看板的写面只有一条腿（唤醒，且本骨架连这条都只给 stub），其余全程零写入。 |
| 7 | **不按 thread 起会话** | 会话是人的入口，thread 是卡的分组。两者不互相生成 —— 一旦互相生成，转发层就会无限长。 |
| 8 | **不做一键安装器 / 不做系统服务** | 本仓只有 CLI。装成服务是安装器的事，不是工具的事。 |
| 9 | **不内置任何家规检查** | 谁家的 DoD、谁家的回写纪律，都不该混进来 —— 混进来就变成"我们的工作流"而不是"一种设计"。 |

## 三条设计取舍（做的时候的现场记录）

**① 为什么 `say` 的闸只有两道（不是三道）**

投给已归档会话是白投：宿主会在 `agent/pre-step` 拒掉这次投递、回合以 `blocked` 收尾、
**不发模型请求**，而投递接口本身仍回"已受理" ⇒ 投递方拿到"已通知"的假象，消息在界面里根本看不见。
这类"看着成功、实际没人读"的错最难自察，所以闸必须放在**打印预览之前**（预览看着正常 = 等于没拦）。

第三道「已交接」闸属于某些部署自己的交棒语义（标题带标记就不投），不是通用能力 ⇒
降级成可选配置、默认关。通用件不该假装自己有某个别人家的规矩。

**② 为什么 `reset` 不清空任何东西**

"重置"听起来该把上下文清掉，但自动清空是不可逆的：还没落档的结论会跟着一起没。
所以本件只做"把该记住的写成一段可以直接贴的接续头"，清空那一步留给人按（`/compact` 或开新会话）。

**③ 为什么槽位是 16 行 × 120 字**

上下文里对每条线只留一行，是为了让主会话能长期活着。行数上限决定"最多同时跟几条线"，
字数上限决定"每条线留多少信息"。两个数都是经验值，写在 `router-act.mjs` 顶部，
要调就同时调常量与 preset 里那一段 —— 两处不一致时，人以常量为准、preset 那段是给模型看的提醒。
